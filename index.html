Notes from the Build

Vol. 1Go · Backend

What I Learned Building My First REST API in Go

Building my first REST API in Go helped me move from understanding individual programming concepts to understanding how a real backend application is structured. Before this, I knew syntax — variables, functions, loops. Building an actual API forced me to understand how everything fits together as a system, not isolated pieces.

  • Routes and handlers — how requests get matched to code, and why thin handlers keep a codebase maintainable.
  • Services — separating business logic from handlers made debugging and testing genuinely easier, not just "cleaner."
  • DTOs — why you don't expose database models directly; they let you control exactly what data leaves the system.
  • Validation — catching bad input at the boundary instead of chasing bugs deeper in the system.
  • Error handling — meaningful, consistent error responses instead of a blanket 500 for everything.
  • Caching — new territory: when to cache, what to invalidate, and how it can quietly introduce bugs.
A "simple CRUD API" is never really simple — there's a lot of thinking behind making it reliable, maintainable, and predictable.
Vol. 2PostgreSQL · Databases

Understanding PostgreSQL: Joins, Indexes, and Things I Got Wrong

Working with PostgreSQL taught me that good backend development isn't just about writing queries that work — it's about understanding why they work, and what happens when they don't.

  • Table relationships — foreign keys changed how I think about schema design, not just querying after the fact.
  • Joins — learning to think about which join actually answers the question I'm asking, not just one that returns data.
  • Indexes — not a "just in case" addition; they're a trade-off between read speed and write cost.
  • Nullable fields — a small schema decision that caused real bugs in joins and filters.
  • Debugging migrations — going straight to the database to see what's actually happening, instead of trusting the ORM blindly.
I stopped treating the ORM as a black box. Understanding what's actually happening at the database level made me a lot more confident debugging real issues.
